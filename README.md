# 顶点色复制工具 (Blender Vertex Color Tool)

在两组模型之间，根据**位置接近度**和**几何相似度**自动批量复制顶点色。
适用于 LOD 分级、资产变体、同一批模型的快速上色等场景。

- **许可**：MIT ｜ **作者**：StarAsh042 ｜
  **兼容**：Blender **3.2+**（依赖 `mesh.color_attributes`）

---

## 安装

**方式一（推荐）**：从
[Releases](https://github.com/StarAsh042/Blender_VertexColorTool/releases)
下载 `Blender_VertexColorTool-<版本>.zip`，在 Blender 的
`编辑 > 偏好设置 > 插件 > 安装` 中选择该文件，勾选启用。
**方式二（源码）**：`python scripts/build_zip.py`（产物在 `dist/`）。

**关于原生加速库（可选）**：发行包内已附带 Windows x64 的
`native/bin/vct_native.dll`。它是**可选的**——加载失败时自动回退纯 Python，
功能不受影响，只是慢一些，因此 macOS / Linux 可直接使用。
面板「优化处理 → 原生加速」会显示当前是否已启用。
自行编译（需 Zig 或 g++/clang++）：`pip install ziglang && python native/build.py`

启用后，3D 视图右侧边栏（按 `N`）会出现 **「顶点色复制」** 标签页。

## 快速上手

面板「自动处理工具」的三步工作流：

1. **指定两组集合**：「参考组」放已上好色的模型（颜色来源），
   「目标组」放待上色的模型。
2. 点「**1. 分析集合**」，确认两组网格数量与带色物体数量符合预期。
3. 点「**2. 查找匹配**」，结果出现在「匹配结果」列表
   （格式 `源物体 → 目标物体  置信度`）。
   **逐条复核后**，选中误匹配的条目点「移除选中匹配」剔除，
   再点「**3. 复制顶点色**」。执行期间可按 **ESC** 取消；
   聚类模式下还会显示分组编号（`组0`、`组1`…）。

> 匹配只是**按位置与尺寸推荐**，不保证正确——复制前请务必复核，
> 详见「已知限制」第 1 条。

## 手动工具

| 工具 | 说明 |
|------|------|
| **选择无顶点色 / 不纯顶点色** | 在场景可见物体中筛选没有顶点色 / 颜色「不纯」的网格 |
| **选择颜色 / 应用颜色** | 填充选中物体；编辑模式下只填充选中顶点 |
| **清除颜色** | 删除选中物体的**全部**顶点色层（有二次确认） |
| **通道预览 R/G/B/A/RGBA** | 以灰度方式单独查看某个通道，点 RGBA 恢复 |
| **复制顶点色** | 手动复制：**先选目标物体，最后选源物体**（活动物体即源） |

**关于通道预览的安全性**：预览会临时修改顶点色数据，工具会先在网格上
创建一个名为 `__vct_preview_backup__` 的**真实备份颜色层**保存原始颜色。
点「RGBA」即恢复并删除备份层。即使预览状态下保存 `.blend` 或 Blender 崩溃，
原始颜色依然保留在备份层中。

## 参数说明

**匹配预设**：快速匹配（默认，平衡）/ 精确匹配（收紧）/ 宽松匹配（放宽）/
聚类匹配（目标组内相似物体归为一组）/ 自定义（不覆盖任何参数）。

| 分类 | 参数 | 说明 |
|------|------|------|
| 基本 | **最大匹配距离** | 比的是**物体原点**（`obj.location`）的世界坐标距离，不是包围盒中心。默认 50 |
| 基本 | 尺寸 / 体积 / 顶点数 / 距离权重 | 四维相对重要性（内部归一化） |
| 高级 | 相似度阈值 | 低于此值的候选直接丢弃。默认 0.7 |
| 高级 | 位置衰减系数 | 越小则距离影响越缓和 |
| 高级 | 最小置信度 | 低于此值不进结果列表。默认 0.6 |
| 高级 | 使用聚类 / 聚类阈值 | 聚类模式下物体间相似度门槛。默认 0.8（**会被预设覆盖**） |
| 优化 | 使用当前激活层 / 指定层名 | 复制到哪一层 |
| 优化 | 使用 KDTree 加速 | 源物体顶点数超 20000 时**强制启用**（关不掉） |
| 优化 | **法线夹角阈值** | 默认 75°，防薄壁跨面。**设为 0 = 关闭并恢复原生加速；设为 >0 会自动切 Python 路径**，见 docs/LIMITATIONS.md 9.1 |
| 优化 | **取色距离上限** | 默认 0 = 关闭；防超范围「拉色」，超距顶点保留原色。设为 >0 会自动切 Python 路径，见「已知限制」8 |
| 优化 | 分批处理数量 | 每批物体数，控制内存峰值。默认 10 |
| 优化 | 缓存 / 内存优化 | 源数据按对象复用、分批触发 GC |
| 优化 | 缓存内存上限 | 默认 256 MB。大模型单条即可占数百 MB |

## 算法说明

1. **特征提取**：每个物体取位置、包围盒尺寸、体积（包围盒近似）、顶点数。
2. **相似度评分**：位置用指数衰减（按物体平均尺寸归一化），
   尺寸/体积/顶点数用归一化差值，四者加权平均，输出 `[0, 1]`。
3. **匹配**：为每个目标物体（或每个聚类）挑选相似度最高且超过阈值的参考物体。
4. **颜色传递**：**源侧与目标侧的处理并不对称**，需分开看：
   - **源物体**：顶点位置与颜色同取自**同一个求值后网格**，索引天然对齐，
     带修改器不影响取色结果。工具在源顶点上建 **KDTree**，
     并整理出「源顶点下标 → 颜色」映射。
   - **目标物体**：对目标物体的每个顶点，用该 KDTree 查找**最近点**，
     取最近点的颜色。但——
     **顶点坐标取自求值后网格（含修改器结果），颜色却写入原始网格**。
     两者顶点不再一一对应，目标物体带拓扑修改器时索引会错位
     （详见「已知限制」第 7 条）。

## 性能

「物体匹配」与「顶点色复制」两个热点由 C++ 原生内核执行
（ctypes 加载纯 C ABI 动态库，内部多线程）。
实测（Blender 3.4.1，Windows x64）：

| 场景 | 纯 Python | 原生 C++ | 加速比 |
|------|-----------|----------|--------|
| 顶点色复制（2 万顶点 × 10 个目标） | 3438 ms | **250 ms** | **13.7x** |
| 物体匹配（600 × 600 = 36 万次比较） | 5835 ms | **17 ms** | **352x** |
| 物体匹配（2000 × 2000 = 400 万次比较） | — | **81 ms** | 约 50 M 次比较/秒 |

**数值一致性**：原生内核**不会改变计算结果**。
`tests/test_native_equivalence.py` 用同一份输入分别跑 C++ 与 Python 实现并逐项比对，
匹配结果与复制出的顶点色均完全一致。唯一已知差异：并列最近邻（距离完全相等）时
两种实现可能选中不同顶点——两者都是正确答案。

## 已知限制

完整 **25 条**见 [`docs/LIMITATIONS.md`](docs/LIMITATIONS.md)，
含每条的完整原因、影响场景与应对方式。
下表按「会不会让你拿到错误的结果」排序，**前 8 条是结果正确性相关**，建议先读。

| # | 限制 | 应对 |
|---|------|------|
| 1 | 匹配只看位置、尺寸、顶点数，**不看形状 / 朝向 / 法线 / 拓扑**；且「体积」是包围盒三边之积，与「尺寸」**同源重复计分** | **始终逐条复核「匹配结果」**，不要直接点「3. 复制顶点色」。形状差异大的场景切「自定义」，把尺寸/顶点数权重调低、距离权重调高，用位置邻近性兜底 |
| 2 | 匹配特征取自**原始网格**（`vertex_count` 是修改器前的值），与取色阶段（用求值网格）口径不一致 | 批量前让参与匹配的模型处于一致的细分状态；差异大时把「顶点数权重」调低 |
| 3 | 一个源物体可被任意多个目标物体共用，**匹配不是一对一** | 把「通用型」模型拆到不同集合分批处理，或调高阈值把可疑匹配挡在结果之外 |
| 4 | 「最大匹配距离」比的是**物体原点**，不是包围盒中心也不是表面最近距离 | 批量前先统一原点（`Object > Transform > Origin to Geometry`），大场景再调大该值 |
| 5 | 四个权重**全部为 0** 时不报错，而是完全不匹配 | 至少保留一项不为 0；切一次预设可一次性恢复全部参数 |
| 6 | 「低于 60% = ❌」这一档在**默认参数下不会出现**——「相似度阈值」0.7 已先把候选丢弃，能进列表的天然 ≥ 0.7 | 想让三档配色用起来须把**两个阈值一起下调**（只降后者无效）；复核时以面板百分数为准 |
| 7 | 目标物体带修改器时，颜色索引会错位——目标坐标取自**求值后网格**、颜色却写入**原始网格** | **复制前先应用（Apply）目标物体的修改器**；只影响显示、不改拓扑的修改器（置换 / Wave）不受影响 |
| 8 | 最近顶点取色**默认没有距离上限**，超出源包围范围的顶点会被「拉色」 | 面板设「**取色距离上限**」（按对角线百分比，默认 0=关闭）；或对齐两模型的世界坐标范围 |
| 9 | 不做插值、不做形状对应，只按几何最近点取色 | 源与目标细分层级尽量相近；需要渐变精度请改用贴图 |
| 10 | 颜色空间按数据原样搬运，不做 sRGB/线性转换 | 源与目标用同一种颜色属性类型 |
| 11 | 「清除颜色」删除该网格上**全部**颜色层（含 `__vct_preview_backup__`） | 注意先备份 |
| 12 | 缓存**不因源颜色或源变换变化而失效**（键为「对象地址+层名+顶点数」，而缓存内容是世界坐标） | 改过源颜色 / 移动过源物体后，点「优化处理 → **清空缓存**」，或关闭「缓存」再复制。改拓扑则会自动失效 |
| 13 | 聚类**分组**不走原生加速（簇内匹配已原生化） | 大量物体时仍建议用非聚类模式 |
| 14 | 聚类内部忽略你的权重设置，整簇共用一个源的代表元 | 只能靠「聚类阈值」调节（其数值**会被预设静默覆盖**） |
| 15 | 分批只影响内存；取消检查只在批结束时进行 | 预期要取消就把批大小调小 |
| 16 | 「手动复制」没有进度条，也无法取消 | 大模型下慎用，否则只能强杀进程 |
| 17 | 大网格上有若干硬编码阈值不可调（如单条缓存**估算字节数**超出内存预算即不予缓存） | 防卡死兜底，无需干预 |
| 18 | 界面仅有中文，未接入 Blender i18n | — |
| 19 | 原生加速只随发行包提供 Windows x64 | 其他平台自动回退 Python |
| 20 | Blender 版本检查只打印警告，不会阻止启用 | 以 3.2+ 为准 |
| 21 | 预览通道的备份层会残留在网格上 | 预览完务必点「RGBA」再保存 |
| 22 | 匹配结果按物体名保存，改名或删除后失效（会计为失败，不会静默错配） | 改名后重新「查找匹配」 |
| 23 | 匹配/统计**递归含所有层级子集合**（v1.1.0 行为变更），不能用子集合做范围隔离 | 需要隔离请改用多个互不嵌套的顶层集合分批 |
| 24 | 只处理网格物体，且以物体模式读写 | 编辑模式填充前先明确选中范围（**未选中顶点会填满整个网格**） |

第 7 条是**静默写错顶点**且不报任何错——细分 / 镜像 / 布尔 / 实体化 / 简化等
**改变拓扑**的修改器都会触发，表现为花斑、错位或只写进去一部分。
源物体一侧不存在这个问题（源的颜色和坐标同取自求值网格）。

### 9.1 薄壁模型可能跨面取色；可用「法线夹角阈值」缓解

最近邻只看**距离**，不看**朝向**。对薄壁几何体（墙、树叶、旗帜、布料、
单面片建模的护甲/门板/卡牌等——**LOD 游戏资产里非常常见**），
壁两侧的顶点距离几乎相等，最近点可能落到**另一面**上，
表现为「墙背面染上了墙正面的颜色」。该问题**没有任何报错或警告**，
工具会正常返回成功。

**⚠ 关键：开启阈值后会自动改用 Python 取色路径，不再走原生加速。**
原因是原生 C++ 内核的最近点查询只按距离、不看法线，**尚未实现法线约束**。
若不禁用原生加速就会「界面显示已启用、实际毫无作用」。

| 法线夹角阈值 | 取色路径 | 说明 |
|---|---|---|
| `0` | **原生 C++ 内核** | 默认，最快；不防跨面 |
| `>0`（如 75） | **Python** | 防跨面；大模型明显变慢 |

- **设为 0 即完全关闭**，退回纯距离最近，便于遇到「某些模型取色反而变差」时快速回退对比。
- **调不奏效时会退回纯距离最近**（附近没有朝向一致的候选，例如单面片、法线未烘焙、
  稀疏网格）。这是刻意兜底——优先保证「不丢色块」，所以串面重新出现属预期，**不是 bug**。
- **不是万能解**：只解决「跨面」，不解决速查表第 9 条的「色块感 / 噪点」。
- **取舍是零和的**：不在意串面就留 `0`（享受原生加速），遇到串面才开，
  无需在正确性与速度间妥协。
- 完整说明（float64 精度红线、20 万顶点实测代价、调不奏效的兜底逻辑）见
  [`docs/LIMITATIONS.md`](docs/LIMITATIONS.md) 第 9.1 条；
  面板「优化处理」会显示当前实际走的是哪条路径。

## 常见问题

| 现象 | 排查 |
|------|------|
| 「查找匹配」结果为空 | ① 参考组里是否有带顶点色的网格；② 「最大匹配距离」是否太小（默认 50，且比的是**物体原点**，见限制 4）；③ 「相似度阈值 / 最小置信度」是否过高；④ 参考组与目标组是否选反了 |
| 复制完颜色不对 / 看起来没变化 | 确认目标物体的顶点色层与工具设置一致；确认视口着色模式能看到顶点色（材质需用 Color Attribute 节点） |
| 卡住不动 | 大模型 + 关闭 KDTree 会极慢。源物体顶点数超 20000 时会自动启用 KDTree；仍很慢则调小「分批处理数量」并保持「内存优化」开启 |
| 预览通道后颜色变灰 | 点「RGBA」恢复。原始色保存在 `__vct_preview_backup__` 备份层 |
| 「清除颜色」能撤销吗 | 该操作声明了 `UNDO`，正常可 `Ctrl+Z`。但它删除的是颜色层，重要文件请先备份 |

## 开发

```bash
python scripts/run_ci_checks.py                                    # 快速检查（无需 Blender，CI 同款）
python scripts/run_blender_tests.py --blender "<Blender 路径>/blender.exe"   # 4 个 Blender 测试文件
python scripts/run_blender_tests.py --list                        # 只看会跑哪些文件
```

> **为什么要用执行器而不是直接跑 `tests/`？** `tests/` 下的脚本
> **只打印汇总、不设退出码**，而 Blender 的 `--python` 无论成败都返回 0
> ——直接用退出码判定会「全红也变绿」。
>
> ⚠️ **退出码约定**：`0` 通过 / `1` 失败、无结果或**有文件被跳过而未加
> `--allow-skip`**。**跳过 ≠ 通过**——跳过的文件其覆盖路径本次是盲区。
> `tests/test_native_equivalence.py` 在原生库缺失时会**整体跳过**
> （连汇总行都不打印）；此时不加 `--allow-skip` 会返回 `1`，
> 加了则该盲区被显式记录、需自行判断。
> Blender 本身缺失也是 `1`（这些用例走 `bpy`，**无法用替身替代**，
> 不允许降级为跳过）。

**修改原生内核后**：`python native/build.py` 重新编译，
再跑上面的测试执行器，**必须全绿**。⚠️ 请保持 `double` 内部运算精度——
Python 版使用双精度，若内核改用 float32，会在阈值边界产生足以
**翻转匹配结果**的偏差。

**扩展指引**：新增算子/面板在对应模块定义即可（`__init__.py` 自动收集，
新模块需登记到 `_CLASS_MODULE_ORDER`）；
新增匹配维度要同时改 `core/matching.py` 的 `SIMILARITY_METRICS`、
`_compute_metric_scores` 与 `properties/settings.py` 的权重属性；
新增预设改 `MATCH_PRESETS` 与 `match_preset_items`。

**可立即做（S）**：面板内参数速查表（「最大匹配距离」比的是物体原点，

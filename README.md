# 顶点色复制工具 (Blender Vertex Color Tool)

在两组模型之间，根据**位置接近度**和**几何相似度**自动批量复制顶点色。
适用于 LOD 分级、资产变体、同一批模型的快速上色等场景。

- **版本**：1.0.0
- **作者**：StarAsh042
- **许可**：MIT
- **兼容**：Blender **3.2+**（依赖 `mesh.color_attributes`，该 API 自 3.2 引入）

---

## 安装

### 方式一：直接下载发行包（推荐）

从 [Releases](https://github.com/StarAsh042/Blender_VertexColorTool/releases) 下载
`Blender_VertexColorTool-<版本>.zip`（也可直接取 `dist/` 目录下的同名文件），然后：

1. Blender → `编辑 > 偏好设置 > 插件 > 安装`
2. 选择该 `.zip` 文件
3. 在插件列表中找到「顶点色复制工具」，勾选启用

### 方式二：从源码自行打包

```bash
git clone https://github.com/StarAsh042/Blender_VertexColorTool.git
cd Blender_VertexColorTool
python scripts/build_zip.py      # 产物: dist/Blender_VertexColorTool-<版本>.zip
```

打包脚本会自动从 `__init__.py` 的 `bl_info` 读取版本号，并自检产物完整性。
之后按方式一的步骤安装该 zip。

启用后，在 3D 视图右侧边栏（按 `N`）会出现 **「顶点色复制」** 标签页。

> 从源码目录直接使用：把**本项目文件夹的父目录**加入 `sys.path`，然后
> `import Blender_VertexColorTool; Blender_VertexColorTool.register()`。

## 快速上手（自动流程三步）

面板中的「自动处理工具」提供三步工作流：

### 1. 准备两组集合

- **参考组**：已经上好顶点色的模型（颜色来源）。
- **目标组**：需要被上色的模型（颜色接收方）。

在「集合选择」面板中用搜索框分别指定这两个集合。

### 2. 点击「1. 分析集合」

统计两组的网格数量与带顶点色的物体数量，结果显示在面板上。

### 3. 点击「2. 查找匹配」

为每个目标物体寻找最相似的参考物体。完成后结果会出现在
**「匹配结果」面板**的列表中，格式为 `源物体 → 目标物体  置信度`。

- 置信度 ≥ 80% 标记为 ✅，60–80% 为 ℹ️，低于 60% 为 ❌。
- 可以选中某一条点「移除选中匹配」，把明显错误的匹配剔除掉。
- 聚类模式下还会显示分组编号（`组0`、`组1`…）。

### 4. 点击「3. 复制顶点色」

按匹配结果批量复制。执行期间会显示进度条，**按 ESC 可取消**。

## 手动工具

「手动处理工具」面板提供：

| 工具 | 说明 |
|------|------|
| **选择无顶点色** | 在场景所有可见物体中，选中没有顶点色的网格 |
| **选择不纯顶点色** | 选中顶点色「不纯」的物体（含混合色或多种颜色） |
| **选择颜色** | 常驻颜色选择器，配合「应用颜色」使用 |
| **应用颜色** | 把当前颜色填充到选中物体；编辑模式下只填充选中顶点 |
| **清除颜色** | 删除选中物体的**全部**顶点色层（有二次确认） |
| **通道预览 R/G/B/A/RGBA** | 以灰度方式单独查看某个通道 |
| **复制顶点色** | 手动复制：**先选目标物体，最后选源物体**（活动物体即源） |

### 关于通道预览的安全性

预览会临时修改顶点色数据，但工具会先在网格上创建一个名为
`__vct_preview_backup__` 的**真实备份颜色层**保存原始颜色。

- 点「RGBA」即恢复完整颜色，恢复后备份层自动删除。
- 即使预览状态下保存 `.blend` 或 Blender 崩溃，原始颜色依然保留在备份层中，
  **不会永久丢失**。

## 参数说明

### 匹配预设

| 预设 | 适用场景 |
|------|---------|
| **快速匹配** | 默认，平衡速度与质量 |
| **精确匹配** | 缩小匹配距离、提高阈值，追求准确 |
| **宽松匹配** | 放宽距离与阈值，尽量多匹配 |
| **聚类匹配** | 目标组内相似物体归为一组，共用同一个源物体的颜色 |
| **自定义** | 不覆盖任何参数，完全手动调 |

### 基本参数

- **最大匹配距离**：两个物体中心点的最大距离，超过则不匹配。
- **尺寸 / 体积 / 顶点数 / 距离权重**：四个相似度维度的相对重要性（内部会归一化）。

### 高级参数

- **相似度阈值**：低于此相似度的候选直接丢弃。
- **位置衰减系数**：越小则距离影响越缓和，较远的相似物体也可能被匹配。
- **最小置信度**：低于此置信度的匹配不会进入结果列表。
- **使用聚类 / 聚类阈值**：聚类模式下目标物体之间的相似度门槛。

### 优化处理

- **使用当前激活层 / 指定层名**：复制到激活层，还是复制到指定名称的层。
- **使用 KDTree 加速**：加速最近点搜索。**顶点数超过 20000 时会自动启用**，
  以保证不会退化为极慢的暴力搜索。
- **分批处理数量**：每批处理的物体数，用于控制内存峰值。
- **缓存 / 内存优化**：缓存源物体数据、分批触发垃圾回收。

## 算法说明

1. **特征提取**：每个物体取位置、包围盒尺寸、体积（包围盒近似）、顶点数。
2. **相似度评分**：位置用指数衰减（按物体平均尺寸归一化），尺寸/体积/顶点数用
   归一化差值，四者按权重加权平均，输出 `[0, 1]`。
3. **匹配**：为每个目标物体（或每个聚类）挑选相似度最高且超过阈值的参考物体。
4. **颜色传递**：对目标物体的每个顶点，在源物体顶点的 **KDTree** 中查找最近点，
   取该点颜色写入。顶点位置与颜色都取自**同一个求值后网格**，
   因此带修改器（细分/布尔/镜像等）时索引依然对齐。

## 常见问题

**Q：点「查找匹配」后结果为空？**
A：依次检查：① 参考组里是否有带顶点色的网格；② 「最大匹配距离」是否太小
（默认 50，大场景可能需要调大）；③ 「相似度阈值 / 最小置信度」是否过高；
④ 参考组与目标组是否选反了。

**Q：复制完颜色不对 / 看起来没变化？**
A：确认目标物体使用的顶点色层与工具设置的层一致（「优化处理」面板中的
「使用当前激活层」或「指定层名」）。另外请确认视口着色模式能看到顶点色
（材质需使用 Color Attribute 节点）。

**Q：为什么卡住不动了？**
A：大模型 + 关闭 KDTree 会极慢。工具在顶点数超过 20000 时会自动启用 KDTree；
若仍然很慢，请调小「分批处理数量」并保持「内存优化」开启。

**Q：预览通道后颜色变灰了，怎么恢复？**
A：点「RGBA」按钮即可恢复。若已在预览状态下保存文件，重新打开后同样点
「RGBA」恢复（原始色保存在 `__vct_preview_backup__` 备份层中）。

**Q：清除颜色后能撤销吗？**
A：该操作声明了 `UNDO`，正常情况下 `Ctrl+Z` 可撤销。但由于它删除的是颜色层，
建议重要文件先手动备份。执行前会有二次确认对话框。

## 开发

### 运行测试

项目自带基于真实 Blender 的无头冒烟测试（覆盖注册、匹配、复制、预览恢复、缓存隔离）：

```bash
"<Blender路径>/blender.exe" --background --factory-startup \
    --python tests/blender_smoke_test.py
```

测试结束会打印 `测试汇总: N/M 通过`。

### 目录结构

```
Blender_VertexColorTool/
├── __init__.py                 # 插件入口：自动收集并注册所有类
├── core/                       # 核心逻辑（不依赖 UI）
│   ├── cache.py                #   顶点色缓存 + KDTree
│   ├── matching.py             #   特征提取 / 相似度 / 聚类
│   └── vertex_color_ops.py     #   复制与填充核心
├── operators/                  # Blender 算子
├── properties/                 # PropertyGroup 数据模型与参数预设
├── ui/                         # 侧边栏面板
│   └── results_panel.py        #   匹配结果列表（UIList）
├── utils/
│   ├── vertex_color_utils.py   # 顶点色工具函数 + 新旧 API 兼容层
│   ├── compatibility.py        # Blender 版本检查
│   └── logging_utils.py        # 统一日志与错误上报
└── tests/
    └── blender_smoke_test.py   # 无头冒烟测试
```

### 扩展指引

- **新增算子/面板**：在对应模块中定义类即可，`__init__.py` 会自动收集注册；
  新模块需要登记到 `__init__.py` 的 `_CLASS_MODULE_ORDER`。
- **新增匹配维度**：在 `core/matching.py` 的 `SIMILARITY_METRICS` 注册一行、
  在 `_compute_metric_scores` 中补上得分计算，并在
  `properties/settings.py` 中加对应权重属性与预设值。
- **新增预设**：在 `properties/settings.py` 的 `MATCH_PRESETS` 中追加一项，
  并在 `match_preset_items` 中加上枚举项。

## 已知限制

- **界面仅提供中文**，尚未接入 Blender 的 i18n 翻译系统。
- 匹配算法为 4 个维度的加权模型，对形状差异大但尺寸相近的模型可能误匹配，
  建议用「匹配结果」面板人工复核。
- 聚类为 O(n²) 的简单层次聚类，目标组物体数量极大（数千以上）时匹配阶段会较慢。
- 复制采用「最近顶点取色」，不做颜色插值，因此顶点分布差异很大的两个模型
  之间可能出现色块感。
